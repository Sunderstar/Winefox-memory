# 私有数据边界与开源发布检查

## 公开发行包清理原则

这份公开发行包使用**严格的文件允许列表**重新构造，而不是在作者原 ZIP 上删除几个文件后重新压缩。

- 没有源项目里的 `.env` 或任何原始密钥。
- 没有源项目里的 `data/`；因此没有 `memory.db`、个人聊天/自主发言、人格卡、Core、原始模型输出、Embedding、召回和错误日志。
- 没有旧升级步骤、私人测试样本、实验对照导出或编译生成的 `__pycache__`、`.pyc`。
- `defaults/winefox.yml` 已由纯中性模板重写，不附带原作者实际人物设定。
- 原开发测试中出现过与作者真实游戏和对话关联的语句，因此公开版使用全新**合成**测试用例，不直接搬运这些私有样本。
- `.gitignore` 默认拒绝提交 `data/`、`.env`、数据库、聊天 JSONL、日志、游戏档案和缓存。

## 为什么不能只删聊天文件？

`memory.db` 内的 `extraction_runs`、`candidates`、`extracted_episodes`、`core_auto_runs` 和其他审计表可能保存原始消息、模型输出及记忆。`data/logs/` 和 Core 历史快照同样可能包含私人内容。只删 `chat_history.jsonl` 并不等于清除个人信息。

此外，Windows 绝对路径、游戏角色标识符、日志堆栈或历史终端截图也可能泄露身份。公开 ZIP 也不能携带 `__pycache__`，因为 Python 字节码可能还原旧文本常量。

## 发布者本地检查

1. 确认发布的是本仓库根目录而不是自己的运行目录。
2. 本地执行 `python -m unittest discover -s tests -q`，确认不需要用户私有数据库也能运行合成测试。
3. 执行 `python tools/public_release_check.py`。该工具检查危险文件路径和常见形式的密钥；此类自动检查**不能证明没有任何隐私**。
4. 用 ZIP 管理器再次检查，确认没有 `data/`、`.env`、`.maid`、聊天导出或任何你自己在使用的真实角色设置。
5. 真实启动和聊天后，新的 `data/` 会自动出现在本地；**请勿将整个运行目录压成新的公开 ZIP**。
6. 如果密钥曾上传到第三方仓库、公开网盘或历史 Git 提交，必须在 API 服务商处撤销并重建，单纯删除文件不够。
7. 发布者应确认代码版权、第三方素材及授权条款，保留 `THIRD_PARTY_NOTICES.md`，不要把他人的人物卡、图片或游戏资源当作原创软件发布。

## 风险说明

公开包不能阻止使用者自行把个人信息写进 `data/`，也不能保证 API 提供方对聊天数据的存储方式。具体隐私政策取决于使用者选择的模型服务商。将来增加 QQ、读图、游戏工具时，需要重新评估访问控制、好友/群聊数据与自动化权限。
